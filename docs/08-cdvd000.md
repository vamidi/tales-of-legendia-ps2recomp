# 08 — `CDVD.000`

Reproduce with:

```
python tools/region_profile.py IMAGE.iso --lba 2311 --size 1073676288 --block 33554432
```

Output: [`reports/cdvd000-profile.txt`](../reports/cdvd000-profile.txt),
[`reports/cdvd000-census.txt`](../reports/cdvd000-census.txt).

---

## The file

```
CDVD.000     LBA 2311 .. 526566     1,073,676,288 bytes     26.31% of the disc
             ISO 9660 stamp 2004-08-11 17:08:31 +9
```

Three things about it are odd before anything is read. Its name is not a name —
`.000` is what a splitter or a mastering tool produces. Its size is 32 sectors
short of exactly 1 GiB. And its timestamp is **eleven months and ten days older
than the next-oldest game file on the disc**, in a set that is otherwise
2005-05-28 to 2005-07-22.

Its first bytes are `FD FD FD FD …`, and `0xFD` fill for a kilobyte in a
gigabyte-sized file with a mastering-tool name is a strong argument for padding.
That was the working hypothesis here and it was wrong, which is why the file
gets its own document.

## What is actually in it

Reading the whole gigabyte and counting bytes:

```
byte 0xFF   349,948,749   32.59%
byte 0x00   347,518,798   32.37%
byte 0x3F     5,136,178    0.48%
distinct byte values: 256
first byte that is not 0xFD: offset 1071
```

Padding does not have 256 distinct values. Profiling it in 32 MB blocks — top
byte, share, and Shannon entropy per block — shows three regions with sharp
seams:

| Region | Bytes | Entropy | Reads as |
|---|---:|---:|---|
| `0x00000000` … `0x18000000` | 402,653,184 | 7.20 – 7.83 | **data** |
| `0x18000000` … `0x1A000000` | ~33,554,432 | 2.01 | transition |
| `0x1A000000` … end | 637,468,672 | **1.000, two distinct values** | pattern |

The tail is 608 MB of a strictly two-valued alternation. The head is 384 MB of
something at 7.8 bits per byte, which is what compressed data looks like.

## It is 1,430 compressed members, and every one of them decodes

Scanning the whole file for the `CPS` magic and validating each candidate's
header arithmetic:

```
CPS-shaped headers   1430
2048-byte aligned    1430 of 1430
first                +0x002699800
last                 +0x018348800
span                 365,621,248 bytes (348.7 MB)
```

**All 1,430 fall on 2,048-byte boundaries.** Random four-byte coincidences in
high-entropy data do not do that; the expected number of `CPS\0` hits in 1.07 GB
of random bytes is 0.25, and the expected number of *sector-aligned* ones is
0.0001. These are real members of a real archive.

Handing every one of them to `tools/cps.py` — the same decoder used on the live
archives, given no hint about the unpacked length:

```
stored members       0
compressed members   1430
decoded exact        1430
mismatched           0
packed bytes         350,345,144
unpacked bytes       683,107,520
ratio                51.29%
```

**1,430 of 1,430.** Zero mismatches, zero exceptions. This is an asset set, in
this game's own compressed format, sitting inside a file nothing on the disc
refers to.

Two more traces confirm it is a build artefact rather than random content:
sweeping the image for `MW MIPS` returns four hits, two of which are inside
`CDVD.000` — so it contains compiled Metrowerks code, not only data. And at
`+0x17F00000` there is a `CPS` member whose payload contains the ASCII tag
**`TLPKv1+50`**, sharing its `TL` prefix with the `TLPS` chunk that wraps every
AHX voice file on the disc.

## Is it the same data as the shipped game?

No. The disc's smallest live member, `FIELD.AFS / field_grd0c_x00y00.mcd.cps`,
is 56 bytes packed and 128 unpacked. `CDVD.000` has a member at `+0x2699800`
that is **50 bytes packed and 128 unpacked** — the same output length, a
different input length, which is exactly the shape of the corpus's "the packer
was run twice on the same file" result from 2003/2004.

It is not that. Decoding both and comparing:

```
CDVD.000  +0x2699800   01 00 00 00 00 00 00 00 80 00 00 00 00 00 00 00 12 00 00 00 40 00 00 00 10 00 00 00
FIELD.AFS field_grd0c  01 00 00 00 00 00 00 00 80 00 00 00 00 00 00 00 16 00 00 00 40 00 00 00 40 00 00 00
```

Same structure, same length, **different contents** — two fields differ. So this
is not one input packed twice; it is an **earlier revision of the same asset**.
Which is consistent with the timestamp, and means `CDVD.000` cannot be used for
the packer measurement the corpus would most like to have.

## What it is, and what is not knowable from the disc

The reading the evidence supports: at some point around **2004-08-11**, roughly
a year before mastering, a build of this game's asset set — 1,430 members, 348.7
MB of live data — was written to a file, and that file was still in the build
tree at mastering time and got included. Its tail was never written, which is why
608 MB of it is a two-valued pattern, and its head was overwritten with `0xFD`
for a kilobyte. Nothing indexes it: `PTN_INFO.BIN` names six archives and this is
not one of them, `FLIST.DIR` lists six paths and this is not one of them, and the
executable's `cdrom0:\` strings name `SLPS_255.33`, `IRX\`, `MBS\` and
`AFS\PTN_INFO.*` and nothing else.

What is **not** knowable from the image is whether including it was deliberate.
There is a real argument that it was. A DVD reads its outer tracks faster than
its inner ones, and `CDVD.000` occupies sectors 2311–526566 — the innermost
region, immediately after the executable and before every archive. A gigabyte
parked there pushes all 1.46 GB of live archives outward onto the faster part of
the disc, and 26% of a disc is an expensive accident. Against that: a deliberate
pad would not normally be a year-old build with real data in it, and it would
not normally have a `.000` name.

The corpus has one prior data point that this bears on and does not settle.
*Tales of Symphonia*'s PlayStation 2 disc left 16.12% of itself empty with 686 MB
in a single interior hole, published as unproven and read as possible head
separation; *Tales of Rebirth* left 0.478% with no interior gap and said that
whatever Symphonia's hole was, it was not studio policy. Legendia has **no
interior gap either** — its slack is 0.53% and all of it follows the last
archive — but it achieves the same *effect* as Symphonia's hole by different
means: a quarter of the disc's inner region is occupied by something the game
never reads. Three discs, three layouts, and the only thing common to the two
that push their data outward is that neither can be shown to have meant it.
